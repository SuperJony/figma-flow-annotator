# Plan Flow Connector route dependencies in core

Shared core should own **Flow Connector** route dependency planning before any runtime gathers geometry for a **Connector Route**. For Create Flow Connector, Refresh Connectors, and Validate Bindings, core should derive the required Figma node ids plus their route roles and classifications, including **Flow Endpoints**, **Owner Context Frames**, **Connector Obstacles**, existing **Flow Connectors**, and label nodes when validation needs them. Runtime adapters may rehydrate those ids into bounds, shared plugin data, and live Figma nodes, then pass runtime facts back through core routing, validation, and **Figma File Operation Batch** APIs. Runtime adapters must not rediscover ordinary route dependencies by scanning unrelated page nodes or deep frame descendants.

The contract is `node ids + role/classification`, not ids-only and not full runtime route facts. Ids-only would leave obstacle and endpoint classification policy in every runtime adapter, repeating the same drift this architecture is meant to remove. Full runtime facts would push Figma-specific geometry and shared plugin data reads into core, breaking the boundary from ADR-0043 and making later agent-skill writers emulate the plugin runtime. Keeping ids and roles in core lets the plugin and later agent skills share routing policy while each runtime stays responsible only for rehydrating facts it can observe.

Broader discovery is allowed only on explicit repair or deep-audit paths, such as Repair Validation State or a future intentional page audit. Ordinary Create Flow Connector, Refresh Connectors, Validate Bindings, and Clean Stale Indexes should operate from selected endpoints, known connector records, validation-index ids, or other bounded dependency ids. If a required dependency is missing, the command should report or preserve the existing route according to its existing semantics rather than silently falling back to full-page traversal.
