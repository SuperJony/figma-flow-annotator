# Use browser visual harness for regression

The first demo should verify **Annotation Card** and **Annotation Badge** visuals, **Flow Connector** visuals, and plugin panel states through a deterministic browser visual harness that reuses the plugin's annotation creation path, route/SVG model, and UI rendering paths, while keeping real Figma desktop checks as low-frequency smoke tests before demo or release. Direct desktop automation is too stateful for routine agent verification, and pure semantic tests cannot show whether annotation cards, badges, **Connector Routes**, arrowheads, **Flow Action** labels, and panel states remain visually readable.
